# Product extraction contract

Extract attributes of the product offered by this record from its observed name, description, manufacturer and price. Return the JSON object defined by `schema.json`. Record identity stays outside the model response. The extractor receives one source record and no candidates, identity labels, source identifiers or partition metadata.

Use only stated facts. A compatible device, included component or alternative edition mentioned in a description is not automatically the offered product. Preserve ambiguity. Use null for an unknown scalar, an empty list for unknown model identifiers or quantities, and `uncertain: true` when the offered product or its relevant attributes are ambiguous. The flag is diagnostic; all records remain in evaluation.

Use at most six model identifiers and six quantities. Quantities retain the explicitly written unit and numeric value. The supported units are TB, GB, MB, kg, g, oz, lb, ml, litre, liter, GHz, MHz, inch, inches, mm, cm, pack, count, user and seat. Do no unit-conversion arithmetic. The deterministic normalizer converts supported units. Counts of software users or seats are licence quantities, not physical pack sizes. Do not infer a quantity merely from the absence of a qualifier.

Keep the product name within 160 characters, manufacturer within 80, and edition, platform and licence within 60 each. Return up to three exact evidence quotes, at most 100 characters each. Quotes must occur in one of the supplied source fields. They verify source presence, not the semantic truth of every extracted attribute. Do not invent a full licence, operating system, version, manufacturer or product alias. Deterministic brand normalization is shared with the conventional comparator.

The adapter `features_from_extraction(observed_record, extraction)` supplies the same Splink comparison schema as conventional parsing. It substitutes extracted manufacturer, offered-product model identifiers, explicit quantities and the product-name/edition/platform/licence representation, while retaining original descriptive evidence and observed price. It applies generic normalization and unit conversion in code. The comparison specification and label-free fitting procedure remain fixed; EM is fitted afresh for the extracted representation.

`run_recordwise(left_rows, right_rows, extractions_by_id, candidates, output_dir, prior_bundle=...)` accepts observed five-field records and independent per-record extractions. The required prior bundle copies `main_prior` and the complete `priors` dictionary from the conventional split's `splink-fit-audit.json`. Extracted agreement counts cannot change these numeric priors. The same frozen probability-regularization and failed-fit rules apply to both representations. The function never opens reference labels. It produces all-pair scores and decisions plus scores on the unchanged conventional candidate union. These represent separate full-universe and candidate-controlled comparisons. Missing or invalid model responses must be recorded by the caller, remain in the attempted denominator, and be passed as null; the adapter uses a deliberately empty extraction for that record, retaining only its original descriptive evidence and observed price. Its manifest saves `failed_extraction_ids`. This does not convert a failed call to a valid automatic decision.

The initial output allowance is 512 tokens per record. Any different source truncation, schema, prompt or allowance must be frozen before that batch starts.
